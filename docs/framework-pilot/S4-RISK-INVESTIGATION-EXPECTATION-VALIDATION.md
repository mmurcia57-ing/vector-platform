## Semantic corrections required
The executable product MUST NOT infer requirements/facts from illustrative concept content including:
- incident/risk IDs and dates;
- impact/customer/user counts;
- latency/error/SLO values;
- specific services, dependencies, databases or infrastructure;
- Dynatrace, CloudWatch, Git or OTEL as authoritative configured sources;
- deployment/change identifiers;
- “possible cause” labels as causal proof;
- hypothesis probability/confidence percentages unless a legitimate defined model produces them;
- root-cause certainty;
- environment/team/owner names;
- suggested actions or deadlines;
- Prod/Lab;
- any action/control without specified behavior and authorization.

## Required epistemic model
S4 must visibly distinguish:
1. **OBSERVED FACT / SOURCE EVIDENCE**
2. **DETERMINISTIC DERIVED FINDING**
3. **CORRELATION / TEMPORAL ASSOCIATION**
4. **HYPOTHESIS / CANDIDATE EXPLANATION**
5. **LIMITATION / UNKNOWN**
6. **GOVERNED DECISION**
7. **COMMITMENT / ACTION**
8. **EXECUTION EVIDENCE**
9. **VERIFIED OUTCOME**

No visual proximity, temporal proximity, topology relation or AI narrative may silently promote an association into causality.

## Investigation progression

`OPEN → EVIDENCE COLLECTION → HYPOTHESES/CANDIDATES → VALIDATION → GOVERNED DECISION → COMMITMENT/ACTION → EXECUTION EVIDENCE → OUTCOME VERIFICATION → LEARN/CLOSE`
